# Gummy Actor–Agent Technology Position

**Author and originator:** Hayden Lindley  
**Recorded publicly:** July 27, 2026  
**Technology:** Gummy OS Actor–Agent Framework

## Public Position

Gummy OS is Hayden Lindley’s independently developed, human-centered Actor–Agent operating environment.

The primary object is not a chatbot, model, app, file, or autonomous agent. It is the **Actor**: a persistent, evolving, governed representation of a human being and the knowledge, capabilities, preferences, relationships, Projects, and unfinished intentions that belong to that person.

An **Agent** is a replaceable execution runtime acting for an Actor under bounded authority. Models and agents may change. The Actor and the continuing Project do not disappear with them.

The Gummy architecture combines:

1. persistent human Actor identity;
2. strict separation between Actor and Agent;
3. structured retrieval and generated operational memory governed by source, evidence, conflict, scope, acceptance, expiration, and rollback;
4. an inspectable windowed environment containing Actors, Agents, Sessions, Projects, Productions, tools, and live processes;
5. durable collaboration objects that survive beyond a chat transcript or live transport room;
6. bounded authority that travels with delegated work;
7. mandatory Return to the Actor, Session, Project, or Production that caused the work;
8. Evidence and Receipts describing what was requested, authorized, done, changed, returned, and accepted;
9. human or explicitly governed acceptance before proposed output becomes canonical state;
10. continuity from ideas and conversation through creative production, software, publishing, protection, collaboration, and physical realization.

Canonical operating loop:

> **IDENTIFY → INTEND → MAKE → RETURN → ACCEPT → RESUME**

Canonical definition:

> **Gummy OS is an Actor-centered operating environment in which persistent human identity coordinates replaceable agents through governed operational memory, inspectable windows, bounded authority, durable collaboration, evidence, Receipts, and mandatory Return to accepted Project state.**

## Foundational Distinctions

### Actor before Agent

The Actor is the durable human continuity layer. The Agent is a worker.

### Memory is proposed, not silently true

Generated operational memory must preserve provenance and pass the correct acceptance process before becoming Actor or Project truth.

### Windows are operational surfaces

The technology claim is not the visual rectangle. It is the use of persistent, addressable, permission-aware windows for Actors, Agents, Sessions, Projects, tools, and processes participating in a shared operating system.

### Return is mandatory

Work is incomplete while trapped inside another model, IDE, browser, agent, or service. It must return to its originating context.

### Acceptance creates canonical state

Generation and action produce proposals. Acceptance determines what the system treats as true or complete.
